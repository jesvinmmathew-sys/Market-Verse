# Security policy

## Reporting a vulnerability

Please do not disclose vulnerabilities, credentials, tokens, personal information, or exploit instructions in public issues or pull requests.

If GitHub private vulnerability reporting is enabled, use **Security → Report a vulnerability** on this repository to contact the maintainer privately. If that option is unavailable, open an issue titled **Private security contact requested** containing only a request for a private reporting channel. Wait for that channel before sharing sensitive details. No private email address is published here.

Include the affected commit, a concise description, expected and observed behavior, impact, and minimal reproduction steps using synthetic data. Redact credentials and personal information. Coordinate public disclosure with the maintainer after assessment and remediation; no response-time or bounty commitment is currently offered.

## Scope and maintenance

Reports are welcome for the current repository code, including the Express API, authentication integration, AI/provider access, account-scoped client state, spreadsheet imports, and build configuration. Maintenance focuses on the latest source revision; there is no separately maintained release support matrix.

Use a local environment and accounts you control. Avoid accessing other users' data, disrupting the public demo, exhausting paid API quotas, or testing third-party services without their authorization. The demo's account-access restriction does not replace vulnerability reporting or imply security certification.
